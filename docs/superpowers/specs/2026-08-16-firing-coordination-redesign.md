## 1. 设计原则（全部硬性）

1. **有界等待**：所有 `while` 等待必须有超时；超时后路径必须收敛（尽力击发 / 干净 Failed + 诊断），绝不依赖看门狗兜底
2. **失败可诊断**：卡死时日志必须能定位（膛内快照：弹种/装药/CanFire/状态机 stateKey/确认按钮活性）
3. **读取失败 ≠ 业务状态**：`-1` 是"无法确认"，不是"装药不足"，不得触发破坏性动作（退壳）
4. **破坏性动作幂等**：退壳/清理必须有前置条件检查（膛空则无事可做）
5. **好管不被坏管拖死**：单管故障不得传染（等待、协调必须容忍对方停滞）

## 2. 决策点 ⚠️

### D1 炮塔锁的持有粒度

| 方案 | 持锁期 | 装填期转方位 | 风险 |
|---|---|---|---|
| A 现状 | 任务开始 → 击发完成 | 后台持锁转（移动目标） | 后管等锁死等（P3）；锁几乎总被占用 |
| B 仅击发段 | 瞄准收敛 → 击发完成 | 无锁自由转 | 双管同时装填时抢舵不收敛 |
| **C 瞄准段起持锁**（推荐） | **装填完成(PostLoad) → 击发完成** | 无锁**不**转（单管场景可由后台无锁预转） | 需要证明：双管自动模式下装填期转向收益≈0（两管装填期重叠，座圈一个方向只能服务一管） |

- C 的关键收益：装填期无锁 → 后管装填完成即抢锁（锁几乎必空闲）→ **P3 死等消失**；锁只在瞄准+击发段被持有（~10-20s），等待有界
- 单管场景保留装填期预转：后台协程在**锁空闲且另一管未在瞄准/击发**时无锁预转（无抢舵对手）

### D2 有界等待清单（所有等待加超时 + 停滞检测 + 诊断）

| 位置 | 现状 | 改为 |
|---|---|---|
| FSC:1216 等锁 | 无界（P3） | 超时 `LockWaitTimeout=60s` → Failed + 快照日志 |
| FSC:1408 非持锁者等持锁者 | 无界（P1） | 超时 `PartnerWaitTimeout=20s` → 本管尽力自打（持锁后 Fire）；持锁者停滞检测（对方 progress 不动 10s → 放弃等） |
| FSC:1404 WaitFire | 无界（P2） | 超时 `WaitFireTimeout=20s` → 每 5s 打膛内快照；超时后 Failed（不重试同一发） |
| FSC:1329/1359/1377 冻结窗口协调 | 90s + ToF 差 | ⚠️ D3 决定 |

### D3 齐射协调取舍 ⚠️（推荐：先 Ready 先打）

- 现状：冻结窗口（Paused/Opening）等另一管 Ready + ToF 对齐，最长 90s（P1 的直接现场）
- 日志证据：等齐射的收益（双发同落地白嫖窗口）**远小于**把已装填好管拖到看门狗取消的代价；且协调只在冻结窗口有意义
- 推荐：**取消所有跨管等待**，一律"先 Ready 先打"；保留"同方位齐射门"（`SameBearingAsOther` 放行非持锁者）但非持锁者等锁有界（D2）
- 冻结窗口的收益改由**调度层**实现：farFirst 排序（长 ToF 先派）已存在，够用；不再在击发段等

### D4 `-1` 装药语义

- `ChamberCharges()=-1` = **读取失败/无法确认**，语义改为：
  - 复用判定（FSC:1053-1079）：仅当 `>= 0` 且 ≥ 所需才复用；`-1` → **走标准装填（补装药），不退壳**
  - 弹种匹配且 `CanFire` → 直接按实装打（不读装药）
  - 退壳重装仅限：**弹种不匹配** 或 **实装明确 < 所需（非 -1）**
- 装药读取改健壮：`currentSelectedCharges` 反射失败时重找 `PowderChargeController`（热重载/场景切换后引用失效）

## 4. 验收标准

1. 双管自动模式连打 10 分钟零卡死（无看门狗取消）
2. 单管故障场景（人为制造装填卡死）：另一管照常击发，不被拖死
3. 紧急移动（CBT Critical）：完成后双管正常装填，无"手动转移误判"，无 20s 推弹超时
4. 所有卡死路径 30s 内自行收敛（击发/放弃二选一）+ 日志可定位
5. 静态目标：装填完成后方位已预转到位的比例 ≥ 现状（单管场景）
